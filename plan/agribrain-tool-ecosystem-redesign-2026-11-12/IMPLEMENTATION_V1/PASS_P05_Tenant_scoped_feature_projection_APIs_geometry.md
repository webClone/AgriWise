Project existing authoritative source systems into a stable, read-only map feature envelope. Do not fabricate geolocation, coverage, scientific authority or physical-action status. Separate source owner, spatial support, temporal knowledge and display eligibility. Preserve existing signed Python APIs.

## Implementation packages — in exact order
### P05.01 — Define feature envelope and validators
Fields: contract version, immutable ID+source version, owner scope, entity kind, geometry/CRS/epoch/location source, spatial support, observed/first-available/valid/published times, canonical snapshot/run/experiment refs, epistemic class, quality and trusted provenance refs. Reject unexpected geometry, stale/foreign owner or unsupported types.

### P05.02 — Owner-scoped sensor location adapter
Resolve registered lat/lng/zone/depth from authoritative registry/DB using plot authorization. `sensors/status` currently omits positions; implement new read-only projection rather than treating last reading as GPS. Missing location -> list only. Backend active/retired status remains separate from reading freshness.

### P05.03 — Device/camera/photo/ground-truth adapters
Use true registered camera position/bearing/FOV only when available; photo/site only if geotagged. PTZ simulation flagged. Ground truth object scope point/zone/plot/raster/event; plot-scoped photo does not get centroid pin.

### P05.04 — Drone plan versus flight adapters
Plan path from planned waypoint array, route feasibility, mission identity; executed track exclusively from authenticated flown GPS telemetry. Distinct temporal and epistemic states. Orthomosaic footprint from qualified photogrammetry metadata with QA+provenance.

### P05.05 — MESIA receiver and coverage adapters
Receiver capability/antenna geometry epoch must be present for spatial point. Frequency coverage alone is NOT a geographic polygon; map coverage graph only where qualified geospatial extent and time/frequency support exist. Unknown remains unknown.

### P05.06 — Field event/operation adapters
Normalize rainfall/sensor alert/irrigation detected/scouting task/drone image capture with actual source geometry or none. No artificial event pins. Event persistence and retained revision history required before claim of durable operational alert.

### P05.07 — SIRE+ASMAE projection boundary
Return only authoritative Layer10 map-ready surfaces/zones/manifest lineage through existing signed path. New features endpoint must not bypass `classifyCanonicalHeadValidation`, source policy, render receipts, masks or posterior identifiability.

### P05.08 — Relationship graph as separate service
Create immutable edges `spatially_near`, `overlaps`, `associated_with`, `admitted_by`, `assimilated_into`, `published_as`, `rendered_as`. Only signed source/receipt makes the causal chains; proximity never sets assimilated.

### P05.09 — Pagination and cache safety
Use bbox/time/zoom filters, server caps, stable ordering and cursor for many devices/events. Cache by owner/plot/geometry/time/source version, never globally by plot ID alone. Contract schema versioning, payload size/gzip where appropriate.

### P05.10 — Adapter negative tests
Unauthorized plot; missing device coordinates; foreign zone; invalid WGS84; forged claimed location; replay time beyond cutoff; raw RF receiver missing footprint; sensor receipt missing hash; plan cast as flight. All must fail closed for claimed authority.
## Release / adversarial gates
- **P05-G01** All API requests require server-authenticated tenant and plot; no caller-supplied tenant trust.
- **P05-G02** Sensor pin coordinates equal registered device coordinates, not plot centroid.
- **P05-G03** No fake geographic MESIA coverage from frequency range.
- **P05-G04** Plan geometry cannot be used as actual drone flown track.
- **P05-G05** Late-unavailable data excluded from historical-authoritative scene.
- **P05-G06** Exact publication source and numerical hash matches source, not generated by feature API.
- **P05-G07** Relationship graph never infers assimilation from geographic proximity.
- **P05-G08** Missing/invalid geolocation never blocks catalog visibility, only pin eligibility.
