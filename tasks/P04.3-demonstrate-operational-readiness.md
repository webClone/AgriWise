## 2. Technical Analysis & Current Deficiencies

### The Production Vulnerability
While individual layer calculations may function on synthetic mocks, the integrated platform has not demonstrated operational stability under real-world multi-tenant farm workloads:
1. **Memory Spikes:** High-resolution drone orthomosaics ($<5\text{cm}$ GSD) or multi-band spatial grids across 500-hectare fields cause out-of-memory (OOM) crashes in worker pods.
2. **Worker Starvation:** ASMAE background jobs running long-duration matrix inversions can exhaust task workers, starving incoming real-time API requests.
3. **Cascading Timeouts:** When third-party weather APIs or satellite tile servers experience degraded latency, threads block indefinitely without strict timeouts or circuit breakers.

## 3. Implementation Plan

### Step 1: Stress & Concurrency Test Suite
In `tests/load/`:
- Create an automated stress harness simulating:
  - 50 concurrent plot analysis runs across 10 distinct tenants.
  - Ingestion of 200MB multi-spectral GeoTIFF rasters concurrently.
  - Complete simulated external API dropouts (simulating ECMWF/Copernicus downtime).

### Step 2: Implement Circuit Breakers & Memory Windowing
1. **Raster Streaming Chunking:**
   In `layer10_sire/` and `layer05_asmae/geometry/`:
   - Process spatial rasters in $256 \times 256$ windowed chunks rather than loading entire multi-gigabyte numpy arrays into RAM at once.
2. **Strict Timeouts & Cancellation:**
   In `services/agribrain/orchestrator_v2/runner.py`:
   - Enforce an absolute 15-second timeout on synchronous layer execution.
   - Enforce a 300-second timeout on asynchronous ASMAE background jobs with clean SIGTERM / SIGKILL handling.
3. **Database Connection Pooling & Locks:**
   - Replace direct file writes with atomic file rename operations (`tempfile` $\to$ `os.replace`) to eliminate race conditions when multiple workers write worldline events.
