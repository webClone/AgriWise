## 2. Technical Analysis & Code Audit

### 2.1 The Replay Problem
Scientific auditing and compliance require that identical input bundles executed across different nodes produce an identical `run_id` and content hash:
$$\text{run\_id} = \mathcal{H}(\text{tenant\_id}, \text{plot\_id}, \text{timestamp}, \text{input\_hash}, \text{codebase\_version})$$
Currently:
1. `run_id` incorporates `uuid.uuid4()` or non-deterministic dictionary stringification (`str(dict)` without key sorting).
2. Different Python runtime hash seeds randomize dict key orders.
3. In `layer7_planning/engines/ccr_resilience.py`, Monte Carlo simulations do not seed their PRNG with a deterministic hash of the parcel and year, causing identical inputs to generate conflicting strategic crop rotation advice across consecutive runs.

## 3. Implementation Plan

### Step 1: Canonical Content Hashing
In `services/agribrain/orchestrator_v2/hashing.py`:
- Implement `canonical_json_hash(obj: Any) -> str`:
  - Enforce sorted keys (`sort_keys=True`).
  - Strict float rounding (`round(val, 6)`).
  - ISO 8601 UTC timestamp formatting.
  - Return hexadecimal SHA-256 string.
```python
def compute_deterministic_run_id(
    tenant_id: str,
    farm_id: str,
    plot_id: str,
    as_of_time: datetime,
    input_payload: Dict[str, Any],
    code_version: str = "2026.1",
) -> str:
    seed_str = f"{tenant_id}:{farm_id}:{plot_id}:{as_of_time.isoformat()}:{code_version}"
    payload_hash = canonical_json_hash(input_payload)
    full_digest = hashlib.sha256(f"{seed_str}:{payload_hash}".encode("utf-8")).hexdigest()
    return f"run_{full_digest[:16]}"
```

### Step 2: Seed Monte Carlo Engines Deterministically
In `services/agribrain/layer7_planning/engines/ccr_resilience.py` and Layer 7 Risk:
- Seed random number generators using an integer derived from the parcel ID and base year:
```python
seed_val = int(hashlib.sha256(f"{plot_id}_{base_year}".encode("utf-8")).hexdigest()[:8], 16)
```
