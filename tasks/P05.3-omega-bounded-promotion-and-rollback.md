## 2. Technical Analysis & Current Deficiencies

### The Uncontrolled Deployment Threat
Allowing autonomous AI agents to self-promote code or machine-learned weights to production creates severe vulnerabilities:
- A model fine-tuned on a wet spring season might drastically underestimate water stress when summer drought arrives.
- If a candidate model misbehaves in production, there must be a zero-downtime, deterministic mechanism to roll back to the previously qualified model and trace every farm decision affected.

---

## 3. Implementation Plan

### Step 1: Phased Three-Tier Promotion Pipeline
No model can transition directly from training to production. Enforce a strict three-tier deployment lifecycle:
1. **Tier 1 — Shadow Execution (Minimum 30 Days):**
   - The candidate model runs alongside the production model on live incoming data.
   - Predictions are stored for audit; candidate outputs **never reach users or farm actuators**.
2. **Tier 2 — Canary Domain Scoping:**
   - Evaluated on a maximum of 3 opt-in pilot plots within a narrow geographical and crop domain (e.g. Potato in Clay-Loam soils).
3. **Tier 3 — Production Promotion:**
   - Requires cryptographic signature from the Agronomy Review Board.

### Step 2: Automated Drift Detection & Health Watchdogs
In `services/agribrain/orchestrator_v2/watchdogs/model_drift.py`:
- Continuously compute moving average error and residual distribution:
  - If prediction error exceeds $2.5\times$ baseline error for 3 consecutive days, trigger an **Automatic Emergency Rollback**.
  - If a physical conservation violation occurs (e.g. negative water storage or spontaneous energy creation), immediately revoke model authority.

### Step 3: Instant Deterministic Rollback & Decision Tracing
- Maintain an immutable version pointer in the model registry.
- Rollback execution takes $<100\text{ ms}$:
```python
def rollback_subsystem_model(target_subsystem: str, target_version: str, reason: str) -> RollbackReceipt:
    current_active = registry.get_active_model(target_subsystem)
    registry.set_active_version(target_subsystem, target_version)
    
    # Audit log of all runs executed under rolled-back model
    affected_runs = store.query_runs_by_model_version(current_active.model_id)
    return RollbackReceipt(
        subsystem=target_subsystem,
        rolled_back_from=current_active.version,
        restored_to=target_version,
        reason=reason,
        affected_run_count=len(affected_runs),
        timestamp=datetime.now(timezone.utc),
    )
```

## 4. Acceptance Criteria
- [ ] No candidate model can be promoted without completing Tier 1 shadow evaluation and receiving a signed authorization receipt.
- [ ] Automated drift watchdogs detect statistical performance collapse and successfully trigger rollback without human intervention.
- [ ] An emergency rollback restores the baseline model in $<100\text{ ms}$ across all worker threads.
- [ ] Every agronomic decision made by a candidate model is logged and queryable in the rollback receipt.
